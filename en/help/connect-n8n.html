Connect n8n (API for automations)

FilmmakingUI includes a local API so n8n, Make, Zapier or a script can generate images, videos and montages without opening the interface. It uses your own keys (what is spent is billed by the provider, not by FilmmakingUI) and is built, for example, to produce vertical videos in series from a spreadsheet.

Watch it in 1 minute

The fastest way: in Settings → API for automations click the big “Connect n8n in 3 steps” button and follow the wizard (it creates your token with safe values, downloads the flow and tells you where to paste it). The rest of this guide explains the same with more detail.

Before you start

  • You need an active license (the API is also in the 7-day trial) and the app must be open on the computer where it runs.
  • The API is off by default. Turn it on in Settings → API for automations.
  • It is a separate server (port 8780) that, unless you change it, only listens on your computer (127.0.0.1).

1. Create your token (the wizard does it)

The “Connect n8n in 3 steps” button turns the API on, allows spending (with a warning) and creates a token that can spend credits up to $2 a day and expires in 30 days. If you prefer to do it by hand:

  1. Settings → API for automations → tick the box to turn it on.
  2. If the flow will generate (not just read or assemble), tick Allow spending through the API and confirm the warning.
  3. Create a new token: a name (for example “n8n videos”), scope Spend, a daily cap (default $5) and, optionally, an expiry and the IPs it may be used from.
  4. Copy the token and the webhook secret now: they are shown only once. If you lose it, revoke it and create another.

The token is like a password: do not paste it in chats, screenshots or flows you share. You can revoke it any time on the same screen.

2. Spending rules (no surprises)

  • Every request that spends needs max_cost (USD): if the estimate is higher, it is rejected without generating anything.
  • Every token has a daily cap; when reached, the API answers 402 daily_cap_exceeded.
  • Paid requests need the Idempotency-Key header (8 to 64 characters: letters, digits, _ - : .): if n8n retries, you are not charged twice.
  • The global safety switch and your license still apply. Template montages are free (local ffmpeg).
  • Everything generated appears in the Gallery with the origin “API · token name”.

3a. n8n on the same computer (localhost)

The simplest and safest option.

  1. Import the sample flow: in n8n, Workflows → Import from file → docs/ejemplos/n8n_videos_virales.json (in the FilmmakingUI folder; also at https://filmmakingui.com/ejemplos/n8n_videos_virales.json).
  2. Open the Configuración node and paste your token into api_token. Leave api_base as http://127.0.0.1:8780/api/v1.
  3. In the Google nodes (Sheets and Drive) choose your credentials. If you do not want Drive, disable the Subir a Drive node: the link will be the API one.
  4. Create the Ideas sheet with these columns: tema (topic), guion corto (short script), formato (9:16, 16:9 or 1:1), max_cost, estado, video_url, coste_real, coste_estimado, job_id, notas. One row = one idea, with estado = pendiente.
  5. Click Execute workflow. For each row the flow: estimates the cost → if it fits max_cost, creates 3 images → animates them to video → assembles a vertical video with the UGC/TikTok template and the script as subtitles → receives the webhook → writes the link, cost and status back to the sheet.
  6. To run it on its own, activate the flow (it runs every 10 minutes over the “pendiente” rows).

Cost of a test row (3 FLUX.2 Flash images + 3 four-second MiniMax H3 Max Turbo clips at 480p): about $0.33 estimated (less while the H3 Max Turbo promotion lasts). Set a max_cost of 0.5 for that row.

If n8n runs in Docker: inside the container 127.0.0.1 is the container itself. Run n8n outside Docker or use the tunnel in the next section.

3b. n8n on another computer or n8n Cloud (with your Cloudflare Tunnel)

n8n Cloud, Make and Zapier are on the Internet and cannot reach 127.0.0.1. The safe way is an HTTPS tunnel from Cloudflare to your computer (free; you need a Cloudflare account and a domain on it).

Security warnings before opening anything - Always use HTTPS (the tunnel provides it). Never expose port 8780 directly to the Internet or open your router. - Create a dedicated token for this connection, with a low daily cap and an expiry. Do not reuse it for other things. - If you can, restrict the token by IP (n8n Cloud publishes its IPs) and protect the tunnel with Cloudflare Access (service token) as a second barrier. - While the tunnel is up, anyone with your token can spend with your keys up to the daily cap: keep it like a password and revoke it if in doubt. - The computer must be on, with FilmmakingUI open.

Steps (Windows):

  1. Install cloudflared: winget install Cloudflare.cloudflared.
  2. Quick test (temporary): cloudflared tunnel --url http://127.0.0.1:8780 gives you an https://something.trycloudflare.com address that changes every time. Good for testing, not for production.
  3. Permanent tunnel: `` tunnel: filmmakingui-api credentials-file: C:\Users\YOUR_USER\.cloudflared\<ID>.json ingress: service: http://127.0.0.1:8780 ``
    • cloudflared tunnel login (choose your domain).
    • cloudflared tunnel create filmmakingui-api.
    • cloudflared tunnel route dns filmmakingui-api api.yourdomain.com.
    • Create config.yml (in %USERPROFILE%\.cloudflared) with:
    • hostname: api.yourdomain.com
    • service: http_status:404
    • cloudflared tunnel run filmmakingui-api (or install it as a service: cloudflared service install).
  4. In FilmmakingUI, Settings → API, type api.yourdomain.com in Your tunnel domain. The API keeps listening only on 127.0.0.1: the tunnel comes in through there. (The “Allow remote access” box opens the port to your whole network: you do not need it with a tunnel on the same computer.)
  5. In n8n set api_base = https://api.yourdomain.com/api/v1 and your token. The webhooks back work the same: n8n gives a public URL ($execution.resumeUrl) and FilmmakingUI calls it with a signature.
  6. Check: curl https://api.yourdomain.com/api/v1/ping should answer {"ok":true,...} and curl -H "Authorization: Bearer YOUR_TOKEN" https://api.yourdomain.com/api/v1/health, your data.

Signed webhooks

When a job ends, the API sends a POST to the URL you put in webhook.url with an HMAC-SHA256 signature in the X-FilmmakingUI-Signature header (t=<unix>,v1=<hex>), computed with the token's webhook secret over "<t>." + body. Verify it in your receiver and reject anything older than 5 minutes. If your receiver answers with an error, it is retried up to 5 times. Towards the Internet the webhook must be https; http is only accepted towards your computer or local network (local n8n).

Quick reference

Full documentation and a tester at http://127.0.0.1:8780/api/docs (Swagger, works offline): click Authorize, paste your token and use Try it out on /estimates or /jobs, which come with a ready example (FLUX.2 Flash 9:16 image, $0.05 cap).

WhatRequest
Models and pricesGET /api/v1/models?type=video
Estimate without generatingPOST /api/v1/estimates
Create a jobPOST /api/v1/jobs (type: image, video, lipsync, voice, montage; max_cost; Idempotency-Key header)
Status and resultGET /api/v1/jobs/{id} and GET /api/v1/jobs/{id}/files/1
Upload an input imagePOST /api/v1/files (multipart)
Gallery, characters, locations, propsGET /api/v1/gallery, /characters, /locations, /props
Today's spendGET /api/v1/usage

Example (a vertical image, capped at $0.05):

curl -X POST http://127.0.0.1:8780/api/v1/jobs ^
  -H "Authorization: Bearer YOUR_TOKEN" -H "Idempotency-Key: my-first-image-001" -H "Content-Type: application/json" ^
  -d "{\"type\":\"image\",\"model\":\"fal-ai/flux-2/flash\",\"max_cost\":0.05,\"params\":{\"prompt\":\"a lighthouse at dawn\",\"aspect_ratio\":\"9:16\"}}"

Common errors

CodeMeaning
401 unauthorizedMissing or invalid token (revoked, expired or from a disallowed IP?).
403 spend_not_allowedEnable “Allow spending through the API” and use a token with the “spend” scope.
400 max_cost_required / idempotency_key_requiredPaid requests carry max_cost and Idempotency-Key (8 to 64 characters).
409 cost_exceeds_maxThe estimate exceeds your max_cost: nothing was generated.
402 daily_cap_exceededYou reached the token's daily cap (it resets at midnight, Madrid time).
424 provider_key_missingThe provider key is missing: the error says where to get it.
429 rate_limitedToo many requests: wait as Retry-After says.
